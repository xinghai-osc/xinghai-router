## 已修复的七项漏洞

| 编号 | 修复行为 | 回归验证 |
| --- | --- | --- |
| S-01 | 控制台在认证/权限/IP 限流后、第一次读取主体时才进行有界缓冲。控制台与支付表单上限 1 MiB；网关默认 20 MiB、图像默认 50 MiB。已知长度与 chunked 超限返回 413，读取超时返回 408。HTTP/1 提前拒绝会关闭连接并终止读取，避免服务端排空未完成主体时挂起。 | 真实路由读取计数、真实 TCP 未完成主体、HTTP/2 超时、SSE 不受主体读取截止时间影响、被拒绝主体不能清空会话绑定。 |
| S-02 | 持久化邮箱验证时间；历史账户默认未验证，不从管理员角色、旧验证码消费记录推断所有权。未经验证的本地账户不能仅凭邮箱自动并入 OAuth；旧 OAuth 绑定到未验证密码账户的情况同样拒绝。 | 注册与邮箱证明、预注册攻击、旧连接、完整 OAuth callback、过期/并发恢复、撤销失败事务回滚、管理员改邮箱清除验证状态。 |
| S-03 | 密码重置及 OAuth callback 只使用服务端 `site_settings.public_base_url`。缺失、无效或读取失败时拒绝生成链接；不回退到 Host/转发头。只允许 HTTPS origin，loopback 开发地址可用 HTTP。 | 恶意 Host/转发头、配置缺失/查询失败、合法 origin 和 token 转义。 |
| S-04 | `quota_limits.source` 区分 `admin` 与 `self_service`；两者可在同一作用域/窗口并存。用户只能更新、删除自己的 self-service 行，且窗口仅限 day/month/total。历史行保守归为 admin。前端管理员规则只读。 | 用户与管理员相同 scope 并存、管理员行不受自助 upsert/delete 影响、非法窗口拒绝、并发 upsert 与迁移幂等。 |
| S-05 | 明确 Key 的规则按该 Key 汇总；仅指定用户的规则汇总其全部 Key；模型规则再限定模型。全部匹配规则共同约束准入。 | 跨 Key 请求数/Token/费用累加，新 Key 不能绕过用户上限；Key、用户与模型隔离。 |
| S-06 | 每条 WebSocket 生成消息重新鉴权后使用与 HTTP 相同的 Key 频率计数器，限流依赖失败时关闭连接。握手另用独立计数，首条生成不会重复计入生成窗口。 | 真实 WebSocket + PostgreSQL：首条成功、第二条超限不调用上游、服务不可用关闭、共享 HTTP Key 计数。 |
| S-07 | 常规与流式上游客户端不自动跟随重定向，保持管理员显式配置内网/HTTP 上游的原有能力。 | 301/302/303/307/308、同源、跨源及 HTTPS 降级均只发出原始请求，凭据不重放。 |

## 相关加固

- 密码恢复原子替换密码、设置邮箱验证状态、撤销全部会话和 API Key；此前未验证账户还会移除旧 OAuth 连接。旧密码或被移除的 OAuth 身份不能在恢复后竞态创建会话。前端提示了这些变化。
- GitHub token、用户接口状态和非零身份 ID 必须有效，必要邮箱接口失败时拒绝登录。
- 直接 SSE 转发先解析已收到的 usage，再写客户端；下游写入失败不丢失这部分计量。按行实时 flush，读取单行有 2 MiB 上限。
- 对话缓存根目录及日期目录权限为 0700，新文件为 0600；启动时收紧已存在的根目录，无法收紧时启动失败。该措施不替代备份介质和历史外部副本权限管理。
- Docker 构建使用 Go 1.26.10、固定 pnpm 12.14.0，仅允许列出的依赖构建脚本。构建上下文复制补丁与 workspace 配置；Go Docker 构建使用 go.mod/go.sum，不依赖未纳入 Git 的本机 vendor。
- CI 增加 Go 可达漏洞扫描、PostgreSQL 安全回归、Web 构建与依赖审计/补丁回归门禁。

## 部署与兼容性

1. 发布时使用新 Go 工具链重新编译，前端用固定 pnpm 执行 `pnpm install --frozen-lockfile` 后重新构建。锁文件、workspace 配置及 patches 目录必须同时发布。
2. 启动会应用 `133_quota_sources.sql` 和 `134_email_verification.sql`。没有改写历史已应用迁移；迁移本身不访问真实 OAuth/SMTP，也不会批量推断历史邮箱已验证。
3. 在管理端配置可信公开基础地址，例如 `https://router.example`，然后再启用密码恢复与 OAuth。`NUXT_PUBLIC_SITE_URL` 不是该数据库配置的替代品。生产边缘代理仍应限制合法 Host、启用 TLS 并正确配置可信代理；本次未检查或修改线上配置。
4. 需要关联 OAuth 的历史未验证密码账户应走邮箱密码恢复，再重新建立密钥和 OAuth 连接。如果未启用邮件能力，应先由运营配置邮件服务；普通密码登录本身不会被迁移全面禁用。
5. 历史自助配额缺少可信来源记录，升级后保守标记为管理员规则。若运营确认某行应允许用户自行调整，可通过管理员管理流程移除该历史规则，再由用户重建自助预算。
6. 新请求大小限制会拒绝以前接受的超大主体。网关与图片限制可用 `GATEWAY_MAX_BODY_BYTES`、`IMAGE_MAX_BODY_BYTES` 配置为正值；控制台及支付表单保持较小硬上限。
7. `system.manage` 仍是可下发服务凭据的高信任运维权限；不得把它按角色名称当作低权限授权。

## 保留的计费边界

审计把以下两项单列为既有产品/运营边界，本次没有将它们冒充已解决的硬计费保证：

- **订阅及日志型额度仍是软并发额度。** 准入到完成计量之间存在在途超额窗口。此前未完成补丁尝试的信用占位预留不构成金额上界，已撤销，避免引入错扣或预留泄漏。
- **中断流完全没有收到 usage 时仍按既有策略不结算金额。** 已收到 usage 的情况现已避免下游写失败导致丢失。缺失 usage 的估算收费、待对账、订阅次数独立结算属于需要明确产品政策的后续工作。

## 验证范围

安全回归使用本地独立 PostgreSQL 17，认证、配额和最终验证各用独立测试库；未连接业务数据库、真实支付、SMTP 或 OAuth。已运行 Go build/vet/普通全量测试、认证/配额/计费/迁移/WebSocket 定向集成测试、Web frozen install/lint/build、22 项依赖攻击测试与依赖扫描。

更宽范围的数据库集成测试发现两处工作区其他改动相关失败：用量筛选中的 SQL 转义，以及订阅 API 测试把数值 user_id 解码为字符串。这些不属于本次安全修复的成功验证范围，原有工作未被覆盖。Docker daemon 在本会话不可访问，因此未完成容器镜像构建或生产部署验证。
