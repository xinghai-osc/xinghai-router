# 奖励风控

奖励风控覆盖普通注册、OAuth 新账号和每日签到。后台入口为「奖励风控」(`/console/admin-reward-risk`)，包括奖励审核、风险事件、账号限制和规则设置。迁移会启用默认规则；存量奖励视为已发放，不会追溯扫描并批量封号。

## 默认行为

| 规则 | 默认值与处理 |
| --- | --- |
| 观察窗口 | 24 小时 |
| 相同 HTTP 来源注册 | 窗口内第 4 个不同账号起，相关邀请奖励待审核 |
| 相同 HTTP 来源签到 | UTC 当天第 4 个不同账号起，签到奖励待审核 |
| 相同签名浏览器标识签到 | UTC 当天第 2 个不同账号起，签到奖励待审核 |
| 相同邀请人 | UTC 当天第 11 次邀请起，邀请双方的奖励待审核 |
| 名称聚类 | 至少 3 个有关联的账号；Unicode 规范化、大小写折叠、移除空白/标点/格式字符，编辑距离相似度至少 0.85，或相同的数字/随机十六进制后缀模板 |
| 自动封禁 | 同一相关群体在 10 分钟内出现至少 5 个不同账号，其中至少 3 个名称相近，且共享签名浏览器标识，或共享可信 HTTP 来源与同一非空邀请人 |

自动封禁只处理当前触发请求的普通账号；管理员、操作员及有显式权限的账号免于自动封禁。相同 IP、相似用户名、WebRTC 不可用或网络信息不一致，均不会单独导致自动封禁。缺失浏览器采集时仍执行服务端来源与奖励频率规则。

风控设置通过 `system.manage` 权限修改，保存时需要近期身份验证。数据库事务使用统一锁顺序，将规则计数、证据、封禁、奖励申领和钱包变动串行化，使连接同一 PostgreSQL 的副本得到一致结果。该锁优先保证奖励正确性；高注册/签到流量上线前应按实际负载测试等待时间。

## 奖励审核与解封

奖励分为 `pending`（待审核）、`credited`（已到账）、`rejected`（已拒绝）和 `withdrawn`（已撤回）。待审核奖励不会增加可用余额，签到接口返回实际新增金额 0，同时保留计划金额。每笔申领保存当时的精确金额；审批不会按后来的站点奖励重新计算。重复提交、并发审批以及重复撤回不会重复记账。

- 查看奖励及封禁记录需要 `users.read`；查看风险事件需要 `audit.read`。
- 同意或拒绝奖励需要 `wallets.manage` 和近期身份验证。只有待审核申领可以改变处理结果；相同决定可安全重试，已拒绝或撤回的奖励不能重新批准。
- 发放前再次检查收款账号和奖励来源账号；邀请奖励还要求邀请人启用。关联账号被封禁时需先审核该账号。
- 解封需要 `users.manage`、近期身份验证、当前封禁记录 ID 和处理理由。解封记录证据审阅时间，已审阅的旧批量行为不会立即再次触发相同自动封禁。
- 封禁会删除现有会话并撤销 API Key。解封后旧凭据仍然无效，用户需重新登录并创建密钥。已打开的 WebSocket 在下一条请求时重新认证；此前已准入的 HTTP/SSE 请求仍可完成与结算。
- 解封和关闭风控均不会自动发放待审核奖励，需单独审批。签到撤回保留当天记录，避免撤回后重新领取；已被占用或消费的余额不会被强制扣成负数。

## 来源与隐私

WebRTC 只在注册、OAuth 登录入口或签到等明确操作前运行。它创建数据通道，不申请摄像头或麦克风；最长等待 2 秒，仅提交最多 8 个公开 `srflx` 地址。服务端签发 5 分钟、单次使用、绑定浏览器的上下文，OAuth 上下文额外绑定提供方及现有的 10 分钟 state。采集失败会作为未知/失败状态处理，不阻断正常提交。

默认 STUN 为 `stun:stun.cloudflare.com:3478`，可在后台关闭采集或改用最多两个自有 STUN 地址。访问 STUN 会向该服务暴露客户端网络来源。浏览器声明属于可伪造的辅助证据，不用于覆盖 HTTP 来源；签名浏览器 Cookie 表示浏览器配置文件，并非物理设备身份。

风控记录只保存带用途与版本隔离的 HMAC，不保存原始候选地址、局域网地址、SDP 或端口。IPv4 按地址、HTTP IPv6 按 /64 聚合。Cookie 默认有效 90 天；到期上下文、超过 30 天且未被未结申领/封禁引用的观察、解封超过 180 天的封禁记录由现有小时任务分批清理。待审核奖励、活跃封禁及财务记录继续保留。

## 可信代理配置

Go 的 `TRUSTED_PROXIES` 和 Nuxt 的 `WEB_TRUSTED_PROXIES` 默认均为空。应按实际网络拓扑分别配置直接上游代理的准确地址或窄网段：Nuxt 信任 TLS 边缘代理，Go 信任 Nuxt 或直接连接 Go 的可信代理。代理必须正确覆盖单值真实 IP 头并追加/覆盖转发链。应用从 socket 来源开始，从右向左解析可信链；错误、过长或来自非可信客户端的头不会成为用户来源。

Go 经 Nuxt 代理运行却未配置信任时，将只能看到 Nuxt 的连接来源，降低基于真实公网 IP 的识别能力；共享公网代理出口还可能把多人聚为同一来源。不要用信任所有来源作为修复方式。环境变量说明见 [.env.example](../.env.example)。

## 验证

```sh
go build ./...
go vet ./...
go test ./...
TEST_DATABASE_URL='postgres://test:password@localhost:5432/router_test?sslmode=disable' go test -tags integration ./internal/app -run 'TestIntegrationReward' -count=1
```

新增数据库测试使用独立 schema 并应用全部迁移。仓库其他全量集成测试会重置 public schema，因此 `TEST_DATABASE_URL` 必须始终指向可丢弃的专用测试库。

从 `web/` 运行：

```sh
node --test tests/risk-context.test.mjs tests/reward-risk-ui.test.mjs tests/proxy-headers.test.mjs
pnpm run lint
pnpm run build
```

采集器自动测试使用受控 WebRTC 替身；真实 STUN 连通性取决于用户网络、浏览器和部署配置。
